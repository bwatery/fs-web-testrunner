## 1. 业务规则一：医嘱开立与开始时间继承规则

### 1.1 业务背景与临床痛点
在临床病房日常开立医嘱过程中，医生通常一次性针对患者下达一组输液或多个连续用药。若每新增一行医嘱，系统都默认重置为当前系统时间（如精确到秒的当前时刻）或留空，会导致：
1. **录入负荷翻倍**：医生必须每次手动选择日期和时间；
2. **用药时序混乱**：同一次查房下达的同批次用药，因录入间隔几秒/几分钟导致开始时间参差不齐；
3. **护士排班困难**：护士站无法判定该批次用药是否属于同一给药轮次。

### 1.2 规则详细规范
* **【规则 1.1：时间继承触发】**：
  * 当医生在住院医生工作站点击 **【+ 新增】** 按钮添加新医嘱行时；
  * 系统前端模型自动检索当前表格中上一条处于 **“暂存 (Draft/SV)”** 状态医嘱的 `startTime`（开始时间）；
  * 新增行的 `startTime` **必须无条件继承并填充上一条暂存医嘱的开始时间**；
  * 仅当当前表格无任何暂存医嘱（即新增当天首条医嘱）时，才默认赋予当前系统时间（或科室排班默认执行轮次时间）。
* **【规则 1.2：同组医嘱时间联动】**：
  * 若新增行为同组医嘱（同组输液，标记为同组号 `groupNo` / `combId`）；
  * 无论同组医嘱何时新增，其 `startTime` 必须强制与主药（首药）完全一致；
  * 若医生回退修改了主药的 `startTime`，同组所有子医嘱的 `startTime` 必须**联动自动同步更新**，不允许存在组内时间分歧。
* **【规则 1.3：长期与临时医嘱分立隔离】**：
  * 长期医嘱 Tab 与临时医嘱 Tab 相互独立；
  * 长期医嘱的时间继承仅取长期医嘱列表上一条暂存医嘱；
  * 临时医嘱的时间继承仅取临时医嘱列表上一条暂存医嘱。

### 1.3 前端与后端模型映射
* **前端模型字段**：`row.startTime` (`YYYY-MM-DD HH:mm:ss`)
* **数据库存储字段**：`MED_IP_ORDER.START_TIME` (DATE / TIMESTAMP)
* **状态判定条件**：`row.orderState === 'SV'` (Saved/Draft)

## 2. 业务规则二：同组输液医嘱频次与用法强一致性规则

### 2.1 规则详细规范
* **成组标识符**：同一组输液挂同一个组号（`groupNo`）与组合号（`combId`），界面以成组符号标记（首药 `┌─`、辅药 `├─`、尾药 `└─`）；
* **【频次一致性】**：同组所有医嘱的执行频次（`freqId`，如 `每天一次 (QD)`、`每天两次 (BID)`）必须完全一致；
  - 严禁出现溶媒为“每天一次”，而溶入的注射液为“每天两次”；
* **【给药途径一致性】**：同组所有医嘱的给药途径（`usageId`，如 `静脉输液`、`静脉滴注`）必须完全一致；
  - 严禁主药为“静脉输液”，辅药为“口服”或“肌肉注射”；
* **【修改联动约束】**：在医生站修改主药的频次或用法时，系统弹窗确认或自动批量更新同组所有辅药。

## 3. 业务规则三：中西药物理隔离与草药付数规则

### 3.1 规则详细规范
* **分立开立原则**：中药饮片/草药与西药/中成药必须分属不同处方/医嘱类别；
* **草药特定必填项**：
  - 中药饮片医嘱必须强制录入 **付数/剂数 (`DOSE_COUNT`)**，默认 1 付，范围 1~30 付；
  - 必须绑定煎服法（`BOIL_WAY`，如：先煎、后下、包煎、烊化、常规水煎）；
  - 饮片单味药计量单位必须为 `g`，不可成组混入西药静脉输液中。

## 4. 业务规则四：抗菌药物皮试闭环强制拦截规则

### 4.1 规则详细规范
* **皮试目录判定**：凡属于青霉素类、头孢类、破伤风抗毒素等标注 `SKIN_TEST_FLAG = 1` 的药品；
* **医生站前置拦截**：
  - 开立时系统强制弹出皮试选项：`[需皮试]`、`[原液免试]`、`[近期已做免试]`；
  - 若选择 `[需皮试]`，系统自动联动生成一条对应的临时皮试医嘱（如“青霉素皮试 1次”）；
* **护士站执行阻断**：
  - 护士站在核对皮试主药时，若皮试医嘱的结果未录入为 **“阴性 (-)”**，系统强行阻断主药的核对与执行打签；
* **药房发药阻断**：
  - 中心药房住院摆药时，若检测到皮试未通过或未出结果，摆药机与调配清单标记警告并禁止扣减库存发药。

## 5. 业务规则五：医嘱生命周期单向状态机流转法则

### 5.1 状态定义与流转图
```
[医生站录入] ──> 暂存 (SV) ──> 已提交 (SB) ──> [护士站核对] ──> 已核对 (VF) ──> 执行中 (ET)
                    │               │                                │
                    └──> 物理删除    └──> 医生直接撤回                  ├──> 停止 (ST) (长期医嘱)
                                                                     └──> 作废 (CN) (需双签确认)
```

### 5.2 权限与操作约束
| 状态编码 | 状态名称 | 允许的操作与角色 | 撤销/修改规则 |
| :--- | :--- | :--- | :--- |
| **`SV`** | **暂存** (Saved) | 医生站：编辑、删除、调整时间/剂量 | 可自由修改或删除 |
| **`SB`** | **已提交** (Submitted) | 医生站：撤回提交；护士站：核对 | 护士核对前，医生可直接点击【撤回】 |
| **`VF`** | **已核对** (Verified) | 护士站：执行打单、转抄；药房：摆药 | 医生不可直接修改，需护士先“取消核对” |
| **`ET`** | **执行中** (Executing) | 护士站：记录执行时间；药房：发药扣库 | 长期医嘱开出后持续生成每日执行档 |
| **`ST`** | **已停止** (Stopped) | 医生站：录入停止时间；护士站：核对停嘱 | 长期医嘱生命周期终止，停止后不再生成执行档 |
| **`CN`** | **已作废** (Canceled) | 医生站：申请作废；护士站：确认作废 | 医嘱无效，若已计费需联动退费 |

## 6. 业务规则六：预交金余额与欠费警戒线动态防护规则

### 6.1 计算公式
$$\text{可用可用额度} = \sum \text{预交金总额} - \sum \text{已发生记账费用总额}$$

### 6.2 欠费分级管控
1. **绿色正常期**（$\text{可用额度} > \text{警戒线}$）：无任何限制；
2. **黄色预警期**（$0 \le \text{可用额度} \le \text{警戒线}$，默认 200 元）：
   - 医生站开医嘱提示：“患者预交金不足，请提醒催缴”；
   - 允许常规基础治疗用药开立；
3. **红色欠费阻断期**（$\text{可用额度} < 0$）：
   - 医生站：阻断非抢救类大额检查（CT/核磁）、限制自费高值耗材开立；
   - 药房站：住院摆药时提示“患者欠费，拒绝调配”，需科主任或院总值班授权。

## 7. 业务规则七：先退药后退费实物与财务严格分离冲正规则

### 7.1 业务核心原则：**实物未入库，财务不退钱**
严禁收费处在未得到药房实物确认的情况下直接办理红字冲正退款，以防国有资产流失。

### 7.2 流转闭环步骤
```
[第一步: 护士站] 发起退药申请 (指定退药科室、药品、批号、退药数量)
      ↓
[第二步: 住院药房] 药房收药验收，核验实物完好性与批号，点击【确认退药】
      ↓
[库存变动] 对应西药房药库实时库存数量: STOCK_QTY = STOCK_QTY + 退药数量
      ↓
[第三步: 住院收费处] 调取已审批退药单，执行记账冲正 (负数冲正流水) 并退还现金/原路退款
```

## 8. 业务规则八：出院登记与出院结算“五前置”强拦截规则

### 8.1 结算硬性前置条件矩阵（五必须）
出院结算窗口在点击【结算】按钮时，系统后端必须依次执行 5 道硬性前置校验，任一不满足即刻弹窗拦截并指引责任科室：

| 校验序号 | 拦截项目 | 校验目标数据表 | 拦截判定条件 | 责任角色与修复指引 |
| :---: | :--- | :--- | :--- | :--- |
| **1** | **长期医嘱未全部停止** | `MED_IP_ORDER` | 存在 `ORDER_CLASSIFY_TYPE='L'` 且 `STOP_TIME IS NULL` 且 `ORDER_STATE NOT IN ('ST', 'CN')` | 住院医生：下达停止时间并由护士核对停嘱 |
| **2** | **临时医嘱未全部执行** | `MED_IP_ORDER` | 存在 `ORDER_CLASSIFY_TYPE='S'` 且 `ORDER_STATE IN ('SB', 'VF')` 未执行未作废 | 住院护士：执行医嘱或由医生作废 |
| **3** | **在途药房摆药单未完成** | `PHA_IP_DISPENSE` | 存在处于“申请中/调配中”尚未完成发药或退药的单据 | 中心药房：完成发药调配或取消调配 |
| **4** | **在途退药退费单未确认** | `FIN_IP_APPLY` | 存在 `APPLY_STATUS = '0'` (申请未确认) 的退药单 | 住院药房/护士站：处理完毕退药申请 |
| **5** | **床位占用未释放** | `COM_BD_BED` | 患者所在床位 `BED_STATE = 'O'` (占用) 且未办出院转出 | 住院护士：病房管理中执行“出院转出/释放床位” |
