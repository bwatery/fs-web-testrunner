## 一、第一项 · 沙盒模式杜绝 24 条假失败（方案红线彻底修复）

### 1. 根因清理
- **彻底删除假数据源**：从 `fs_runner/cases/closed_loop/closed_loop.py` 中彻底删除了 `_MockConn` 和 `_MockCursor` 类定义。
- **杜绝数据源注入崩溃**：不再向被测流程塞假连接对象导致流程拿到 `None` 或 `[]` 抛出 `TypeError: 'NoneType' object is not subscriptable` 或 `AttributeError: '_MockCursor' object has no attribute 'description'`。若沙盒环境下意外试图建立数据库连接，直接抛出 `RuntimeError` 拒绝。

### 2. 前置门禁拦截（而非吞异常兜底）
- **复用声明式前置条件层**：在 `fs_runner/core/preconditions.py` 的 `PreconditionManager` 中扩充 `check_oracle_precondition(env_obj)` 方法。
- **前置阻断判定**：在 `closed_loop.py` 的用例循环调度中，检查前置门禁：
  - 若用例命中造数闸门（`L6-001`, `L6-009`, `L6-012` 且 `FS_ALLOW_CREATE_PATIENT=0`），正常调用流程，由流程首行闸门返回「跳过」；
  - 其余 63 条依赖数据库的业务闭环用例，在进入业务流程前被前置门禁直接拦截，赋予状态「未执行」，备注清晰注明：`沙盒模式：未连接数据库，无法验证业务`，并留存 evidence `{"env": "sandbox", "gated_by": "precondition_oracle"}`。
  - 维护了全量 66 条用例的 `_CASE_TITLES` 字典，拦截时标题准确呈现，绝无空白。

### 3. 兜底强化与状态二值性
- **强化 `SandboxEnv.filter_result_status`**：除 `raw_status == "跳过"` 保留外，其余所有状态（含通过、失败、阻塞）一律映射为「未执行」。
