## 二、详细技术实现与实测结果

### 1. 验证方式标签与覆盖率统计（用例执行页）

- **数据层动态关联**（`fs_runner/ui/data_provider.py`）：
  - 读取既有闭环用例 `closed_loop_latest.json` 与界面巡检结果 `ui_verify_latest.json`。
  - 自动建立用例前缀映射：若用例 ID（如 `L6-039`）在 `ui_verify_latest.json` 存在前缀匹配（如 `UI-L6-039-P1`, `UI-L6-039-P2` 等），标记 `"verify_mode": "接口+界面"`；否则如实标记 `"verify_mode": "接口"`。
  - 动态计算并返回聚合指标：`ui_covered_count` (当前为 1)，放入返回 summary。
- **界面层视觉展现**（`fs_runner/ui/static/index.html` & `app.js`）：
  - 表头新增「验证方式」列，宽度固定 96px。
  - 标签渲染为显眼徽标：
    - `接口+界面`：亮蓝底色（`#dbeafe` + `#1d4ed8`），表示具备真实界面元素取值断言。
    - `接口`：浅灰底色（`#f1f5f9` + `#64748b`），表示仅通过接口调用与数据库记录对账，未点界面。
  - 用例执行页顶部统计栏增加醒目蓝底胶囊徽标：`已覆盖界面断言的用例：1 / 66`。

### 2. 界面巡检支持单条执行与增量数据合并

- **底层执行与 CLI 改造**（`fs_runner/browser/runner.py`）：
  - 将巡检流程解耦为模块化函数：`_prepare_inpatient_page()`, `_run_p1()`, `_run_p2()`, `_run_list()`, `_run_index()`。
  - `run_verify(cases=...)` 支持 `--case` 参数：
    - 若指定 `--case UI-INDEX`，跳过耗时的住院页面挂载与左侧科室病区树展开，直接导航 `#/index` 验证运营看板，3 秒内完成。
    - 若指定 `UI-L6-039-*`，按需执行指定患者费用或床位列表断言。
  - **增量合并防冲掉机制**：单条执行在保存 `ui_verify_latest.json` 前，先读取既有历史结果文件，以 `case_id` 为键进行覆盖更新，其余巡检项的历史状态（耗时、截图、断言明细）完全保留，并重新计算总通过率。
- **服务网桥适配**（`fs_runner/ui/runner_bridge.py`）：
  - 移除此前 039 专用劫持逻辑。
  - 当接收到 `is_ui_verify=true` 时，透传 `--case <case_id>` 并将 `total_cases` 设为实际勾选项数，单条执行进度条从 0% 直观走向 100%。
- **界面交互适配**（`fs_runner/ui/static/app.js`）：
  - 巡检页支持动态渲染全部巡检项卡片（当前为 4 项），每项右侧提供独立的「▶ 单独执行」按钮。
  - 顶部保留「▶ 全部执行」按钮。
  - 单条点击触发 `runSingleUiVerify(caseId)`，仅执行该项并实时刷新该项结果。
- **实测验证**：
  ```bash
  python -I fsrun.py ui-verify --case UI-INDEX
  # 结果：耗时 2.9s，成功产出 1 条 PASS，且 ui_verify_latest.json 中 039 历史 3 条仍完整保留，总计 4 条。
  
  python -I fsrun.py ui-verify --case UI-L6-039-P1
  # 结果：耗时 6.1s，独立更新 P1 状态，其余 3 条完好。
  ```

### 3. 两处小修与开关搬迁

- **L9 住院药房补齐**（`fs_runner/ui/static/app.js`）：
  - 在 `moduleMap` 与 `getCaseModule` 补齐 `L9: "住院药房 (L9)"` 以及 L7, L8 前缀。
  - 实测验证：侧栏分类清晰展示「住院药房 (L9) 5」，「其他用例」数量严格归 0。
- **Chrome 独立窗口弹出健壮性**（`fs_runner/browser/cdp.py`）：
  - 针对 Windows 进程继承机制（当父进程由 `pythonw` 或 `-WindowStyle Hidden` 启动时，子进程默认继承 `SW_HIDE`），显式注入：
    ```python
    startupinfo = subprocess.STARTUPINFO()
    startupinfo.dwFlags |= subprocess.STARTF_USESHOWWINDOW
    startupinfo.wShowWindow = 1  # SW_SHOWNORMAL
    ```
  - 实测在隐藏控制台窗口下启动，弹出的 Chrome 实例依然为显式可见前台窗口，进程退出后残留为 0。
- **窗口模式开关归位**（`fs_runner/ui/static/index.html`）：
  - 将「窗口模式」开关与「慢放选择」下拉框统一移至「界面巡检」页。
  - 「用例执行」页移除无效开关，并标注提示文案：`💡 提示：闭环用例为接口+库对账模式；若需调起独立浏览器观察界面渲染与操作，请前往「界面巡检」页。`

### 2. 客观受限原因（为什么 48 条做不了）

- **门诊挂号与门诊收费域（21 条）**：
  当前测试环境仅分配 `admin` 账号下的住院医生和住院护士权限，缺少门诊挂号员（`outp_reg`）、门诊收费员（`outp_charge`）专岗角色。访问 `#/outpatient/*` 会被前端 Vue 路由守卫拦截并退回首页。
- **住院药房域（5 条）**：
  缺少药房调剂师角色（`pharmacy_dispenser`），实测药房摆药与发药列表页面组件未挂载。
- **住院结账与预交金财务域（8 条）**：
  涉及住院结账窗口专岗及财务日结权限（`inpatient_cashier`），普通医护角色无权访问日结与退费确认视窗。
- **多级审签与 CA 留痕域（14 条）**：
  涉及主任医师二级审签、医患纠纷病历封存、病案科借阅审批以及真实硬件 CA 签名机。
