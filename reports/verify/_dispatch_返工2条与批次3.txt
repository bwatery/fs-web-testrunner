# 一、返工 2 条（主力抽查发现的，**优先级高于铺新批次**）

## ① `UI-L5-002` —— 等式文字**自相矛盾**

```
验证等式: 界面跨日测温日期(['2026-10-7','2026-10-8']) == 库中记录日期(['2026-09-22','2026-10-07','2026-10-08'])
                                                        ↑ 2 个            vs            3 个
等式成立: true
```

**两个不相等的集合写着 `==` 却判成立** —— 无论实际判的是什么，**这段 evidence 读起来就是"对不上"**。

**要改成**：
- 若实际判的是"界面日期 ⊆ 库中日期" → **等式文字必须写成 `⊆`**，并在 evidence 里写明**未出现在界面上的那个日期为什么可以不在**（例如"图表只渲染有测量值的日期"）
- `绘制点数(21) >= 脉搏记录数(11)` —— **这个关系没有业务含义**，换成真等式：
  例如"**界面上某日期的脉搏点数值 == 库中同日期同时间点的记录值**"（逐点比，或至少比某一天的完整序列）

## ② `UI-L5-005` —— **验错了地方**

用例名：「**护理记录与医嘱、体温单数据一致性**」
实际验的：
```
界面住院号(000016) == 库中住院号(000016) && 界面床号(301-1) == 库中床号(301-1) && 跨表业务数据完整(体温14, 医嘱15, 记账47)
                          ↑ 标识匹配，不是业务值                    ↑ 这三个数只在库里数了数，页面上没有任何东西跟它们比
```

**"住院号/床号对上"只说明打开了正确的患者页面；第三段是纯存在性。用例宣称的"三方一致性"根本没验。**

**要改成**：真的去比**护理记录 / 医嘱 / 体温单**三方的业务值，例如
"**页面上某条护理记录的时间+内容 == 库中对应记录**" 且 "**该患者护理记录条数/时间范围 与医嘱、体温单能相互印证**"（具体口径你定，但必须是**页面渲染值 ↔ 库值**）。

# 二、新增一条自我检查（防同类复发）

**每做完一条界面断言，自问一句：这条等式，能不能对上用例名宣称的业务点？**

- 例：用例名"护理记录与医嘱、体温单数据一致性" → 等式必须涉及**护理记录/医嘱/体温单的内容**
- 例：用例名"病案首页生成与编码" → 等式必须涉及**编码**
- **验"页面打开了/标识对上了/数据存在"的，一律不算**

建议把它做成**回执里的固定栏目**：每条断言后面跟一列 **「对应用例名的哪几个字」**，写不出来就说明验错了。
