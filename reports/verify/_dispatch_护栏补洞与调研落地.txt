   它意味着"有写操作没被分类"，那本身就是信号。

# 二、采纳调研成果（用户 2026-10-10 批准）

> 参考 [TestChimp 的测试数据隔离指南](https://docs.testchimp.io/guides/gotchas/e2e-missing-teardown-leaks-data/)：
> **"Teardown 是安全网，不是主要的隔离手段"**；核心是 **runId 隔离 + probe 计数断言**；
> 并明确点名反模式 `DELETE ... WHERE x LIKE 'test%'`（宽泛条件会误删他人数据）。

## 2.1 runId 隔离 + probe 计数断言（**最高优先**）

- 每次跑批生成一个 **`runId`**（如 `20261010_1730_a3f1`），**所有造的数据都带上它**
  （现有 `测试建档<时分秒>` 标记要**统一改成含 runId**）
- **probe 断言**：跑批结束断言
  `库中测试标记行数的净增量 == 审计记录的造数条数`
  —— 不等就是有写操作绕过了审计，**直接判本次跑批不通过**
- **purge 只按 runId 精确删，幂等**；**严禁**用 `LIKE '测试%'` 这类宽泛条件
  （我今天差点就这么干 —— 那会连带删掉**别人**的 39 条测试患者。这条写进 `conventions.yaml`）

## 2.2 UI 失败可回放（Playwright trace 的等价能力）

现在界面断言失败只有一张静态截图，排查很难。要求：**UI 断言失败时落一份现场包**
- 失败瞬间的 **DOM 快照**（`document.documentElement.outerHTML`）
- **控制台日志** + **网络请求/响应日志**（含失败请求）
- 截图 + 当时的 `location.hash`
- 打包落到 `reports/verify/ui_traces/<用例>_<时间>/`

> 若环境允许装 **Playwright**（`pip install playwright`），直接用它内置的 trace viewer 更好
> （`--tracing on` 产出可交互回放）。**装不上就用上面的自研等价物，不要卡在这。**

## 2.3 接口契约校验（Schemathesis 的等价能力）

现在 `--api` 探针只验"参数能不能传进去"，覆盖率很薄。要求新增 `fsrun.py api-contract`：
- **数据源**：`data/api_spec.json`（现成的 1590 条路径）
- **每个接口**：按 schema 生成参数组合（必填缺失 / 类型错 / 边界值），断言
  **响应结构与 schema 声明一致**（不只是看 code==200）
- **范围**：全量 1590 条一次跑不完 —— **先覆盖我们 66 条闭环用例用到的接口**，其余按 `--limit` 抽样
- 若环境允许装 **Schemathesis**（`pip install schemathesis`），直接接它；
  **装不上就自研这个生成器，同样不许卡住**

> ⚠️ 契约测试**不得写库**：只允许用 Read 类接口和带非法参数（会被拒绝）的调用。
> 凡是 code==200 且确实写了库的，**要计入造数审计**。
