## 0. 分工逻辑（为什么这么分）

| | 主力（强模型） | 协作方（弱模型 / Antigravity） |
|---|---|---|
| 干什么 | 逆向接口口径、设计"能失败"的断言、判缺陷真伪、给新人造脚手架 | 跑、抄、查、归档、回归 |
| 为什么 | 这些活**判错了会交付假结论**，风险最高 | 这些活**有唯一正确答案**，照着做就行 |
| 产出 | `verify/flows/*.py`、结论、口径文档 | 报告、CSV、回归结果、数据摸底回报 |

**一句话：协作方不产生"结论"，只产生"事实"。**

## 1. 三条红线（协作方必看，违反即返工）

1. **不许改断言、不许改判定逻辑。** 跑出来是"失败"，那就是失败——把**原始输出原样贴回来**，
   由主力判断是"真缺陷"还是"断言写错了"。**自己"修"一下让它变绿 = 交付假结论。**
2. **不许把"没数据/没条件"写成"通过"。** 状态只有三个：通过 / 失败 / 未执行。
3. **不许覆盖这些文件**：`reports/verify/closed_loop_latest.json`（全量覆盖，会冲掉别人的证据）、
   `D:\workapp\ZJCK\HIS_EMR上线测试用例追踪表_合并版.xlsx`（源文件，只读）。
   产出**一律另存**到你自己的文件名。

### 卡 B · 稳定性复跑（主力写完新用例后）

```bash
for i in 1 2 3; do python run_verify.py --closed-loop | tail -3; done
```

- **判定**：三次都是 `通过 N 失败 0`，且 N 相同
- **注意**：这里最容易出**偶发假失败**（造数撞车、共享号源被插队）。
  只要三次里有一次红，就把那次的完整输出贴回来——**这本身就是有价值的发现**

## 3. Antigravity 能额外分担什么

Antigravity 是 IDE 里的 agent，比纯对话的协作方多了**能在工作区里直接改文件/跑终端**的能力，
所以它可以承担**需要连续动手**的活：

- **卡 D/E/F/G 的脚本化**：写一个 `tools/export_*.py` 一次性产出，而不是手工拷
- **把协作产出固化**：`reports/verify/协作产出/` 下维护一份 `README.md` 索引
- **回归自动化**：把卡 A/B 包成一个 `tools/regression.ps1`，一键跑并留档
- **⚠️ 但同样受第 1 节三条红线约束**：不许改 `verify/closed_loop.py` 里的断言与判定；
  要改公共机制**先问主力**
