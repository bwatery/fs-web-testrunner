## 现在要把它做成**全局护栏**（这才是"免得增加垃圾数据"）

闸门只管住了一处。要求补上四条：

### 1. 写入审计 —— 所有写库调用都要被记录
至少覆盖这些接口（挂在 `Ctx.post` 上统一记，别散落在各 flow）：
`/faith/patient/save` · `/faith/patient/activate` · `/faith/finance/outpatient/register/save/preBalance` ·
`/faith/finance/outpatient/register/save/balance` · `/faith/finance/outpatient/balance/save/preBalance` ·
`/faith/finance/outpatient/balance/save/balance` · `/faith/finance/outpatient/apply/refund/apply` ·
`/faith/finance/outpatient/register/cancel`

**记什么**：接口 · 请求关键字段 · 返回 code · **返回的 ID**（patientId / registerId / …）·
所属用例 · 时间。落到**本次跑批的造数清单**（`reports/verify/_created_<批次>.json`）。

### 2. 跑批结束必须**报数**
每次 `run` / `regression` 结束，**打印并在结果 JSON 里带上**：
```
本次造数：患者 0 条 · 挂号 0 条 · 收费 0 条 · 作废 0 条
```
**这个数字要进台账备注。** 造了多少条不许只躺在日志里 —— 这正是当初被抹平的地方。

### 3. 有上限
单次跑批造数**超过阈值（默认 50 条）立即中止并报错**，不许默默跑完。
（阈值可配，但**默认必须开**。）

### 4. `fsrun.py cleanup-testdata`
一条命令按测试标记回滚本次/历史造的数。**必须先 dry-run 列出将删的 ID 清单和行数，`--yes` 才真删。**
删除顺序按子表→父表，删完逐表报数（照我今天手动清 13,672 行的做法）。

### 5. 回归**不许留残留**
`regression` 跑完后，测试标记数据量与跑之前**必须一致**。
不一致 → 报错（除非显式放行）。

### 验收
- 跑一次 `regression` → 结束时报出"本次造数 0 条"，且**库表计数前后一致**
- 故意打开 `FS_ALLOW_CREATE_PATIENT=1` 跑一次 → **报出实际条数**，并能用 `cleanup-testdata` 一键回滚干净
- 故意把阈值调到 2 → 超过就**中止**
