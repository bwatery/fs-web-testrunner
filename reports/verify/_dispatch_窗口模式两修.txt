# 二、「窗口模式」开关挂错了地方（这是用户投诉的主因）

## 现状
全站只有一个开关 `showBrowserCheck`，**挂在「用例执行」页的工具栏上**。但：

```javascript
// fs_runner/ui/runner_bridge.py
if is_ui_verify:
    cmd = ["ui-verify"]; if show_browser: cmd.append("--standalone")   // ← 只有这里生效
else:
    cmd = ["run","--suite","closed-loop", ...]                          // ← show_browser 被丢弃
```

`用例执行` 页跑的是 **66 条闭环用例**（接口 + 库对账，**根本不点界面**）→ **开关在那儿永远没用**。
而真正会开浏览器的 **「界面巡检」页**（`runUiVerifyNow()`，已正确传 `show_browser`）**反倒没有开关**。

## 改法
1. **`用例执行` 页**：把「窗口模式」开关**移除或置灰**，并写明：
   `闭环用例为「接口 + 库对账」，不产生界面操作；要看界面请到「界面巡检」`
2. **`界面巡检` 页**：把「窗口模式」开关**放过去**，并加一句说明：
   `☑ 窗口模式：另起一个独立 Chrome 窗口（不占用你自己的 9222），可看着它一步步操作`
3. **慢放选择**同理 —— 它也只对界面巡检有意义，跟着一起挪
4. **不许留"看起来能用其实无效"的控件** —— 这正是用户被坑的原因

**验收**
- `用例执行` 页：**看不到**一个能勾却无效的「窗口模式」；有指向「界面巡检」的说明
- `界面巡检` 页：有开关 + 说明；勾上后点「立即执行界面巡检」→ **屏幕上真的出现独立 Chrome 窗口**

# 三、独立可见 Chrome 的窗口会被"继承隐藏"（健壮性）

## 现象（主力实测对照）
```
服务以 pythonw + -WindowStyle Hidden 启动 → 起 chrome → 有进程，屏幕上无窗口
普通控制台 启动                          → 起 chrome → 出现可见窗口  ✅
```
## 根因
Windows 下子进程首次 `ShowWindow(SW_SHOWDEFAULT)` 会**继承父进程 STARTUPINFO 的 `wShowWindow`**。
父进程带 `SW_HIDE` → Chrome 窗口被隐藏。**这不是我们能控制的**（服务怎么起不由我们定），所以要自己钉死。

## 改法
`fs_runner/browser/cdp.py` 拉起**非无头** Chrome 时显式传 `startupinfo`：
```python
si = subprocess.STARTUPINFO()
si.dwFlags |= subprocess.STARTF_USESHOWWINDOW
si.wShowWindow = 1              # SW_SHOWNORMAL
subprocess.Popen(args, startupinfo=si, ...)
```
**要做平台判断**（`STARTUPINFO` 是 Windows 专有），别让非 Windows 跑不起来。

**验收**
- **把服务用 `-WindowStyle Hidden` 起**，触发一次窗口模式的界面巡检 → **屏幕上必须出现可见 Chrome 窗口**
- 无头模式**不受影响**（仍然不弹窗）
- 跑完回收正常（端口上 chrome 残留 = 0）
