# 一、现状与问题

上一轮（`0981f83`）我把「只看该模块」挂在了 **分类名那几个字**（`.cat-name`）上：

```javascript
const nameEl = header.querySelector(".cat-name");
nameEl.onclick = (e) => { ... gState.moduleFilter = ...; };
```

**但用户的点击习惯是点整行**，而整行现在的行为是：

```javascript
header.onclick = (e) => {
  if (e.target.tagName.toLowerCase() === "input") return;
  header.classList.toggle("collapsed");     // ← 只折叠/展开，不筛选
  ...
};
```

→ 点模块行 = 折叠/展开，**不是筛选**。用户想要的是**筛选**。

---

# 二、改成什么样

**把「整行点击」的含义改成：只看该模块的用例。**

| 点击位置 | 行为 |
|---|---|
| **模块行**（名字、数量药丸、行的空白处） | **只看该模块的全部用例**；再点一次 → 回到全部 |
| **`▾` 箭头** | **折叠 / 展开**（原来整行的行为挪到这里） |
| **复选框** `☑` | 只管勾选/取消该模块全部用例（保持现状） |

要点：
1. **判断点击目标**，`input` 和 `.arrow` 走各自逻辑，**其余一律当作"筛选该模块"**
2. 选中态要**明显**（该行高亮）—— 用户要能一眼看出"现在是在看 L5"
3. **再点一次同一模块行 → 回到全部**（与「全部」按钮等价）
4. 保持上一轮已有的一致性：**模块筛选与搜索关键字互斥**（进一个清另一个），
   避免两者叠加出空表
5. 「全部」按钮仍然一键清空 模块筛选 + 关键字 + 搜索框

# 三、验收（我做 CDP 实测，模拟真实点击）

1. **点模块行**「住院医生 (L5)」→ 右侧**只剩 L5 的用例**（26 条 × 2 行 = 52 行），
   且**每一行的用例ID都以 `L5-` 开头**（这是关键断言：不能只是数量对）
2. **再点同一模块行** → 回到 66 条（132 行）
3. **点 `▾` 箭头** → 只折叠/展开，**右侧列表不变**
4. **点复选框** → 只改变勾选，**右侧列表不变**
5. 点模块行之后，点「全部」→ 回到 66 条
6. 截图一张"只看 L5"的页面存到 `reports/verify/screenshots/`

> ⚠️ 第 1 条的"每行 ID 都以 L5- 开头"必须真断言 —— 只比数量的话，
> **"筛错了但数量碰巧对"** 也会绿。这正是本项目一直在防的"假绿"。
